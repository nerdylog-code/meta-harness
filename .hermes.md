# Meta-Harness — Hermes Project Instructions

This file is a bootstrap for Hermes, not an architectural source of truth.

Before modifying this repository:

1. Read `PROJECT_BOOK.md`.
2. Read `PROJECT_STATE.md`.
3. Read the ADRs relevant to the current subsystem (`docs/adr/`).
4. Read the current Work Package / task (`docs/work-packages/`).
5. Inspect the existing implementation and tests before adding abstractions.

Authority order:

```
PROJECT_BOOK.md
→ accepted ADRs
→ PROJECT_STATE.md
→ current Work Package
→ code
→ tests
```

## Rules

- Do not redesign shared contracts without Architect approval.
- Do not create a second source of truth.
- Agent identity is independent of runtime/model/session.
- SQLite/event log is canonical state.
- UI is a projection, never canonical state.
- Preserve Windows + Linux.
- Never claim an enforcement level that was not measured.
- Never treat a model saying "done" as acceptance proof.
- Respect single-writer/workspace isolation.
- Preserve approval, budget and security invariants.
- Do not expose or commit credentials, tokens, local secrets or private machine state.
- Do not force-push or rewrite protected/history branches.
- Keep `PROJECT_STATE.md` concise and factual.
- Run the relevant tests before reporting completion.
- If implementation requires violating an invariant, stop and report ARCHITECTURE BLOCKER.

## Milestone gate

A milestone is not closed on a subagent's word. Run the tests, run the relevant E2E, check for
regressions, read `git diff` and the repository state, re-check the original criteria, and record
the evidence. Whoever implemented a critical change does not validate it alone.

## Subagent return contract

A subagent returns `RESULT` / `CHANGES` / `EVIDENCE` / `RISKS` / `NEXT`, and nothing else. A large
log becomes a file plus its path, an excerpt and a conclusion — never tens of thousands of tokens
re-injected into the orchestrator's context.

## When work is complete

Report: files changed; tests run; evidence; limitations; architecture deviations; follow-ups.

## Not stored here

Transient task status, local paths, provider credentials, model-specific secrets, current run IDs
and temporary implementation notes do not belong in this file. Model routing policy lives in the
`model-routing-policy` skill, not here, because it is operational, machine-specific and expires;
architectural decisions belong in `PROJECT_BOOK.md` and the ADRs.
